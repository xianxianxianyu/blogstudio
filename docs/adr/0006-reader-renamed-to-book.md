# ADR-0006：「Reader」退休，那一侧改叫 Book

## 状态

Accepted（2026-08-21）

## 背景

外壳的三个根一直是 **Reader / Context / Writer**（ADR-0003、ADR-0004）。决策者要往里
加网页阅读时发现这个名字有问题，原话：

> 这种网页的阅读，我不是想做在书架里，**书架只是 reader 的一个小部分，reader 是一个
> 很大的概念**。

问题不在于名字不好听，在于**它名不副实，而且是往大了不副实**：

- 那一侧实际只装**书**——一个书架，加上打开的几本书。
- 而 `Reader` 这个名字把整个「阅读」都占了。于是任何一种新的阅读形态（网页、RSS、
  邮件列表、别人的笔记）看起来都「应该」放进去，可它们一个都不适合书架那套形状。

**一个名字比它装的东西大，就会一直把不属于它的东西吸进来。**

## 决策

**`Reader` 这个词整个退休。** 它同时指过两样东西，现在各自换成名副其实的：

| 旧 | 新 | 它到底是什么 |
|---|---|---|
| `Reader`（根） | **`Book`** | 书架 + 打开的书。**它装的就是书** |
| `Reader.tsx` | **`PageView.tsx`** | 渲染**一页** PDF 的画布（视口封顶、框选、文字层） |

第二个不能也叫 `Book`——它不是一本书，是一页。名字要说清它是什么，而不是它长在谁底下。

## 已有的 ADR 不改

ADR-0003 / 0004 / 0005 里还写着 `Reader`。**那是当时的决定，不该被后来的改名覆写**
——改了就是篡改记录。术语表（`CONTEXT-MAP.md`）里加了一条「退休的词」指路，
读到旧 ADR 的人能查到这次更名。

## 代价

1. **网页现在无家可归。** 上一步我把网页条目挂在了书架那个根下（`rootOf("page") =
   shelf`），而根改叫 Book 之后这就不对了——网页不是书。这一条**故意留着不修**：
   它属于「loop / 网页阅读该放哪」那个还没做的决定，现在硬安一个位置只会再改一次。
2. **CSS 类 `.reader` 改成 `.book-view`。** 纯改名，无行为变化。
