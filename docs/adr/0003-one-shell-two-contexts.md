# ADR-0003：一个外壳装两个 context——外壳只路由，不持有领域状态

## 状态

Accepted（2026-08-20）

## 背景

Reader（PDF Studio）与 Context（Context Studio）此前是两个整屏页面，靠书架页上一个
按钮互跳。决策者要一个共同的外壳：左上角活动栏在两者之间切，下面一列**案头**列着
现在开着的东西。

这看着是 UI 的事，实际同时踩到两条已有的决定：

1. **ADR-0002**：「PDF Studio 不写 Context Studio 的库。」两个产品共用一个窗口之后，
   这条还成不成立？
2. **`Workspace` 是严格单文档的**——一个 `docId`、一份 `clips`、一份 `outline`、
   一个 `recognizer`、一个 `chat`。而「一列开着的东西」这个模式的默认含义是
   **可以同时开好几个**。

## 决策 1：外壳只路由

**ADR-0002 管的是写库，不是像素**，所以共用窗口不违反它。但共用窗口会让越界变得容易，
所以把规则写出来而不是靠自觉：

> **外壳不持有任何一边的领域状态。** 它只知道「现在看哪一边」和「案头上有什么」。
> 摘录、目录、context、知识图，一样都不经过它。

判据很硬：外壳这一层**不许 import 任何一边的领域类型**（`Clip` / `Section` /
`Context`）。要用到它们，说明这段代码放错了地方。

## 决策 2：案头上同时只有一项是活的

「同时真开多本」（每本各有自己的 clips / outline / recognizer / chat）要把 `Workspace`
里每一样单数的东西都改成按书分。那是整个应用的脊梁，也是测试最厚的一层。

**不做，而且理由不是省事**：多开的全部收益押在「换书够快」这一个假设上，而**那个假设
还没量过**。先做「案头 + 记住位置」，把换书耗时量出来；真的慢到难受，再谈多开——
那时我们知道自己在买什么。

案头项记住**页码**与**右栏是哪一栏**，切回去回到原处（决策者要的 C）。

## 决策 3：没有「模式」这一层——Reader、Context、每一本书三者平级

第一版做成了「活动栏切模式 × 案头列书」。决策者看过实物之后否掉了：
**Context 的查看页面应该和书混在同一列里，不需要 switch。**

改成一个联合：

    type Active = { kind: "shelf" } | { kind: "context" } | { kind: "doc"; docId }

Reader 与 Context 是两个**根**（永远在，所以钉在上面且不可关闭），下面是打开的具体
页面。点哪个哪个活，仅此而已。

这不只是换了个样子，它删掉了一个**不可能状态**：原先是 `side`（reader/context）＋
`reading`（在读/在书架）两个布尔量表示三种状态，四个组合里有一个是无意义的
（`side === "context"` 时 `reading` 说什么都不算数）。**用不上的组合迟早会被写进某个
条件判断里**，而那种 bug 只在特定路径上出现。

Context 那侧将来长出「打开一张图」这类东西时，它和书一样进下面那一列，联合多一个
分支即可——不需要先切到某个模式里去。

## 为什么不叫「标签页」

`标签` 已经是摘录在页面上的形态（圆点 ⇄ 小窗），`标记` 是颜色分类。再来一个「标签页」，
三个词共用一个字头，代码里 `tab` / `tag` / `label` 挨着放，迟早有人改错一处。

**案头**与**书架**天然成对：书架是库存，案头是工作面。

## 代价

1. **换书不是瞬时的。** 要重读 PDF、摘录、目录。案头长得像标签页，行为却不是——
   这个落差是真实的，只能靠「切换时有明确的加载反馈」来缓解，不能靠假装。
2. **案头不落盘。** 关掉应用再开，案头是空的（照旧自动打开第一本）。它是「此刻手边
   有什么」，与筛选、折叠同一口径。真需要跨重启记住，那是另一个决定，要多一个文件。
3. **案头暂时只有书。** 不是因为设计上排斥别的，而是 Context 那侧还不存在
   「可以开着的一份工作」这个概念——它的术语表里是 context / 主题 / 知识图 / 聚焦，
   没有一个是。结构留好了，等它长出来直接进同一列。
