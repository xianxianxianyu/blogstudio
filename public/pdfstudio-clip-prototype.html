摘录（Clip）生命周期状态机

设计问题：「摘录的生命周期状态机（框选 → 识别中 → 待编辑 → 已入库，标签 圆点 ⇄ 小窗）推过边界 case 后还站得住吗？哪些动作应该合法、哪些应该被禁止？」

⚠ 未定 · 四个边界 case 的暂定默认

  1. 同一区域重复截图 → 默认 合并进已有标签（备选：新建第二个摘录）。
  2. 入库后再改原文 → 默认 禁止（原文已是 context 的 evidence）。
  3. 摘录入 chat 后又被编辑 → 默认 快照（chat 里是贴入那一刻的快照，之后的编辑不回写）。
  4. 删除已入库的摘录 → 默认 摘录删、context 保留，并标记「来源摘录已删」。

这四个默认都是暂定，随时可推翻 —— 原型的目的就是让你在看到它们被触发时说「不对，我想要的是……」。其余规则（原文只准修 OCR 错字、译文/笔记自由编辑、入库生成 context 等）是已定的领域决策，不改。

场景走查

这是 PDF Studio「摘录」状态机的逻辑原型：纯前端单文件、无框架、无服务器、无持久化。第 1 个 <script> 块是可直接搬进真实代码的纯状态机（零 DOM 访问），页面只是它的薄壳。点开走查和自由把玩，看哪些动作被拦下 —— 那些「等等，这里不对」的时刻就是本原型要挖出来的东西。
