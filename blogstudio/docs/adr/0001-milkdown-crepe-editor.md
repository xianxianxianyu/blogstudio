# ADR-0001：所见即所得的编辑器用 Milkdown（Crepe）

## 状态

Accepted（2026-08-20）

## 背景

Writer 的主页面要一个「好用的所见即所得 markdown 编辑器」。自己拿 ProseMirror 搭一个不在
考虑范围内——输入规则、表格、代码块、粘贴清洗、输入法，每一样都是几周的坑。

约束有一条是硬的：**稿子在磁盘上就是一份 `.md`**（ADR-0004 决策 3），人可以拿别的编辑器
直接改。所以编辑器的文档模型与 markdown 之间必须是**可往返的**，不能是「导出时尽量转成
markdown」。

## 决策

用 **Milkdown 的 Crepe**（`@milkdown/crepe`，MIT）。

- **markdown 是它的文档模型本身**（remark AST ⇄ ProseMirror），不是导出格式。往返丢东西的
  风险从设计上就小一档。
- **开箱就是完整的一套**：斜杠菜单、选中工具条、表格、图片、链接、代码块（CodeMirror）、
  LaTeX（KaTeX——仓库里已经有了，问答那侧在用）。
- 主题是一组 CSS 变量，接到应用现有的排版语言上只花了十几行。

## 落选的

| | 为什么不 |
|---|---|
| **BlockNote** | 形态最接近 Notion，但它的真相是自己的块 JSON，markdown 是转换出来的一层。而我们的真相必须是磁盘上那份 `.md` |
| **TipTap** | 底子一样是 ProseMirror，但 markdown 的序列化要自己配一套并自己维护它的边角 |
| **@uiw/react-md-editor** 这类 | 左右分栏预览，不是所见即所得。写文章时它逼着人一直在两栏之间对照 |
| **Lexical** | 好底子，但 markdown 往返同样要自己长出来，且生态里现成的完整编辑器更少 |

## 代价

1. **Vue 跟着进包。** Crepe 的浮层（工具条、斜杠菜单）是用 Vue 写的，而应用这侧是 React。
   它只在编辑器内部用，两边不打架，但打包产物里确实多了一份框架。**换掉它就要自己写那几个
   浮层**——那正是选它的理由，所以这笔账是认的。
2. **编辑器是非受控的。** ProseMirror 自己持有文本：每次按键把 React 里的值再灌回去，光标
   会跳、输入法会断。所以数据流是反的（编辑器往外报，应用层决定何时落盘），换稿子靠换 `key`
   整段重建。这一条在 `DraftEditor.tsx` 的注释里写死了，因为它反直觉。
3. **升级要盯着。** 主题变量与 feature 配置是它的公开面，但我们额外压了几条自己的 CSS
   （正文宽度、内边距），大版本升级时要看一眼。
