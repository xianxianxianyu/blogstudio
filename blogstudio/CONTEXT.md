# Blog Studio

一个 agent 写文章的工作台。从知识库消费 context，产出稿子。

设计文档在 `docs/workflow.md`（工作流、数据模型、eval 规则、任务即图）；这份是**代码里
现在真的存在的那一层**的术语表。两者的差距是有意的，见 `docs/adr/0004` 决策 3。

## 术语

**文章 (article)**：一篇文章。**它就是一份 markdown**——磁盘上是
`<repo>/site/content/blog/<slug>.md`，YAML frontmatter 放机器读的，`---` 之后原样是正文。
把一个 `.md` 丢进那个目录就能打开，不用导入（ADR-0005）。
_Avoid_: 稿子（这个词已退休，见下）、文档（`document` 在 PDF Studio 已经指一本书）

**在架 / 下架**：`draft: false` / `draft: true`。**下架的文章不被构建，同步时从云端消失，
但文件原地不动**——所以「下架」不是「删除」，也不需要任何新机制，Hugo 自带。
_Avoid_: 草稿（跟 Hugo 的 draft 撞）、隐藏、归档

**「稿子 (Draft)」已退休**（ADR-0005）：它原来指「还没发出去的东西」，而那现在只是
**下架**这个状态。一个目录、两个状态，不再有第二套「未完成」。

**回收站**：`<repo>/.trash/<时间戳>-<slug>.md`。删除是移进去，不是消失。
时间戳前缀是必要的——同一个 slug 删两次不能互相覆盖。

**索引**：本地那个 SQLite。**删了能从文件重扫出来，所以它不是真相**（ADR-0005 决策 6）。
它唯一能给、扫文件给不了的东西是**反向问**：这条 context 被哪几篇文章引用过。
_Avoid_: 数据库（听着像真相）、缓存（听着像可有可无，而列表要靠它）

**文章的名字**：**frontmatter 里的 `title`**；没有才退回正文第一个标题行。
与退休前的规则相反，因为那 92 篇的正文里多半没有 H1——Hugo 自己渲染标题。
**一个例外：下架的文章，正文第一个 `# ` 就是它的名字，跟着正文走**——不然 Writer 新起
的一篇会永远叫「未命名」。上架之后名字挂在公网上，就冻住了。

**素材 (material)**：这一问从知识库召回的那几条 context。**召回不按 topic 查**
（`docs/workflow.md` §4④），按语义；**召不到就明说召不到**，宁可一条不给。
_Avoid_: 检索结果（那是 PDF Studio 问文档那一侧的说法，材料在那边是原文的块）

**引用 (citation)**：回答里真的用上的那几条素材，写成 `[ctx:<id>]`。**只认库里真有的 id**
——模型编出来的记号一律不算数。召回了没被引用的另外报个数：那说明库里有相关的东西没被用上。

**写作搭子**：右边那一栏的「问稿子」。**它只说，不动正文**（`docs/workflow.md` §1.3：改动
要么当场被人看见、要么进 review，中间地带不存在。人自己把它给的段落粘进去的那一下，
就是「当场看见」）。

**断言 (claim)**：正文里的**一个段落或一个列表项**。标题、代码块、表格、引文都不是断言。
每一条断言要么带出处（`[ctx:xxx]`），要么标成自己的观点（`[authored]`）——`docs/workflow.md`
§1.5，二选一，没有第三种。
_Avoid_: 块（检索那边的 chunk 也叫块）、句子（粒度不对：人判断的是「这一段站得住吗」）

**出处的记号**：`[ctx:xxx]` 与 `[authored]`，**就写在正文里**，不在旁边的表里
（`docs/adr/0002` 决策 1）。与写作搭子在对话里用的是同一个记号——把它给的段落粘进正文，
出处跟着一起进来了。

**大纲 (outline)**：正文里的标题结构，**从正文现算**，不是单独存的一份数据
（`docs/workflow.md` §2.2 的 `toc` 在这里的形态）。右栏「稿子」那一栏的主体就是它。
_Avoid_: 目录（`Section` 在 PDF Studio 已经指「书的第几页有什么」，那是猜出来的、要人修的；
这边是自己写的标题，永远准）

**检查 (check)**：确定性检查，`docs/workflow.md` §5.1。**一行模型调用都没有**，所以它
随时是新的、不花钱、不需要配置。结论分三档：`blocked`（这篇不能发）、`marked`（值得看
一眼）、`ok`。**它不拦保存**——写到一半的稿子当然是红的。
_Avoid_: 校验、lint（前者听着像格式，后者是代码的词）

**去处 (Destination)**：一个**云端站点**——一台机器（`~/.ssh/config` 里的别名）、
一个远端目录、一个域名（`docs/adr/0004`）。**不叫「源」**：它是去处不是来源；
**也不叫「站点」**：那个词在 PDF Studio 已经指应用内浏览器的白名单（`CONTEXT-MAP.md`）。
_Avoid_: 源、服务器（去处是机器加目录加域名，不是一台机器）、仓库（ADR-0003 里它一度是
本地一份 git 工作副本，ADR-0004 把那个意思收走了）

**中转站**：本地那份博客仓库，统一目录就在它里面。构建与同步都从它出发。
**它是固定的一个，不是可选项**——这正是 ADR-0004 相对 ADR-0003 变掉的那一点。
应用不替你 commit（`.scratch/blog-cms/spec.md` 决策 3）。

**上架是翻译**：`draft: false` 之外还做两件事——`[ctx:xxx]` 落成文末脚注、正文开头与
标题相同的 `# ` 去掉（Hugo 自己渲染 `title`）。手写的 `tags`/`categories` 一个不动。
**一次性、单向、发生在你选定的那一刻**（`blog/operations.ts` 的 `promote`）。

**一次同步 = 两段**：整站构建 → 同步上云。上架、下架、改标签、删除都只改本地文件，
改完唯一要做的事就是同步。**只有第二段不可逆**（`rsync --delete`）。静态站没有
「只上传一篇」这回事：加一篇会改首页、分类页、RSS 和 sitemap。
「按稿子发布」那条四段的路（翻译 → 提交 → 构建 → 同步）和它的「落点」账本已随稿子一起退休。

## 与别的 context 的关系

- 从 Context Studio **读** `context` 当素材；三方共享的只有这一个形状（`CONTEXT-MAP.md`）。
  代码上的表现是：这里只 import `contextstudio/src/context` 的类型，别的一律不碰。
- 与 PDF Studio 之间**没有领域上的往来**。共用的两样东西都是端口：模型客户端与向量服务，
  而且是靠结构类型接上的（`writer-chat.ts` 的 `Model`、`recall.ts` 的 `Embed`），
  没有一条 import 指向那边。
- 界面住在外壳的第三个根里（`docs/adr/0004`）。外壳只路由，不持有这边的任何状态。

## 还不存在的

`docs/workflow.md` 里的这些，代码里一样都还没有，别在读代码时找它们：
**Talk / Studio / Review 三种模式**、**持笔锁**、**revision 与 block 级 diff**、
**eval ⇄ revise 循环**、**闸门**、**Loom（任务即图）**。

现在只有：写、自动落盘、边写边问、问的时候会去知识库找材料、给断言标出处、确定性检查，
以及 **Loop**。**版本**（留一版、取回旧版）曾经有过，ADR-0005 决策 5 退休——人自己写文章
不需要它，改动要找回去 `.trash/` 或你自己的 git。

**Loop** 是定时跑的三阶段流水线：一个 agent 按 prompt 排出一批任务 → 每个任务各有一个
subagent 单独做（**它只看得到那一个任务文件**）→ 一个 agent 按 prompt 把所有 report
收成一份。它**不是** `docs/workflow.md` §3.3 那个「改」模式——那个已改名为 Review，
正是为了不跟这里撞。规则见 `.scratch/loop/spec.md`，代码在 `src/loop/`。

那份清单里最近的一格是 **Review**：可判定的红绿已经在了；可回退的 revision 随决策 5
退休，等 agent 真的开始改文本时再连同 Diff 一起回来。

## Export 的栏目边界（2026-09-09）

Export 管理 Blog、Project、About。Project 的文章放在 `site/content/projects/`，索引和回收站与 Blog 分开；About 使用结构化数据和专属表单。Recommend 及旧 Loop 路径由同步层保护，继续独立发布。具体规则见 [Export](docs/export.md)。
