# PDF Studio — Retrieval Eval

这套 eval 只测一件事：**`Chat` 内部检索缝能不能把一个问题定位到正确的页**。
它不测模型答得对不对（那是 `eval/samples/` 的事），也不测切块策略本身。

数据集在 `questions.md`，语料是 `pdfstudio/eval/papers/` 下的三篇英文论文。

## 它要回答的选型问题

**候选 embedding 在「中文问英文」这一项上的真实差距有多大？**

ADR-0003 选了 bge-m3，理由是跨语言。但那条理由目前只有公开 bench 背书，而公开 bench
的跨语言分数是一堆任务的平均分，语料是新闻、维基、问答对——没有一条是双栏排版、公式密度高、
带表格和页眉页脚噪声的学术 PDF，也没有一条是「读者用中文问英文论文」这个具体动作。
榜单排名换不出我们这条路径上的判断。

所以这套 eval 的产出不是一个总分，而是一个**差值**：

```
Δ = recall@k(en 对译子集) − recall@k(zh 对译子集)
```

`en-01…en-06` 是 `zh-01 / zh-05 / zh-08 / zh-13 / zh-15 / zh-19` 的逐句对译，同页、同依据。
除了提问语言，这两组的一切都相同，所以 Δ 就是**跨语言检索的净损失**，没有别的变量能背锅。

判定用法：

- Δ 接近 0 → 该 embedding 的跨语言能力在我们的语料上是真的，可以选。
- Δ 明显为正 → 中文问句在这套语料上掉分，榜单分数不作数；要么换模型，要么补 hybrid 打分。
- 两个候选之间比的是 Δ，不是绝对 recall。绝对 recall 受切块策略影响，Δ 不受。

zh 全量 20 条给的是绝对水位，六条对译子集给的是干净的因果。两者一起看。

## 怎么用

对每篇论文各建一个索引，用被测 embedding 编码 chunk 与 query，取相似度 top-k 的 chunk。
判定按**页**，不按块：只要 top-k 里有任意一块的 `page` 等于标注页，就算命中。

页码口径与标注一致：`pdftotext -f N -l N <paper>.pdf -`（这三篇里 PDF 物理页与自印页号一致）。

按页判定是刻意的——切块粒度会变（`CHUNK_CHARS` 现在是 600 的硬切），页码不会变。
换了切块策略之后这套标注仍然有效，不用重标。

`na-*` 三条不建索引之外的特殊处理：照常检索，看阈值是否把它们全部拒掉。

## 指标

在 **26 条可答问题**上算：

| 指标 | 定义 |
|---|---|
| recall@1 | top-1 chunk 的页 == 标注页的比例 |
| recall@3 | top-3 chunk 中任一块的页 == 标注页的比例 |

分组报告，缺一不可：**zh 全量（20）｜en 全量（6）｜六条对译子集的 zh 与 en 各自的值**。
只报总分会被 20:6 的条目比例稀释掉跨语言那一项，正好把要测的东西平均没了。

在 **3 条答不了的问题**上算：

| 指标 | 定义 | 期望 |
|---|---|---|
| abstention | 检索返回空（无块过阈值）→ `grounding: 'none'` 的比例 | 3/3 |
| false-grounding | 返回了 citation、把无关原文当依据的比例 | 0/3 |

这三条对应不变量⑤。**答不了却假装有依据是最严重的失败**——读者拿到一个页码，跳过去，
发现那页根本没这回事，对整个引用机制的信任就没了。所以 false-grounding 不是扣分项，是否决项。

## 两个读数陷阱

**一、abstention 满分可以是白送的。** 现有基线 `search()`（`pdfstudio/src/chat/chat.ts`）只匹配
`/[a-z0-9]{3,}/`，中文问句抽不出任何 term，直接返回 `null`。它在 3 条 `na-*` 上是满分 3/3，
在 20 条中文问题上是 0——因为它对中文一律返回空。**永远返回空 = abstention 满分。**
所以 abstention 必须和 zh recall 并排看，单独一个数字没有意义。

这也正是这套 eval 存在的理由：基线在 zh 上的 0 分就是 ADR-0003 说的那条红灯，
现在它有了可复现的数字，而不只是一句「已知不够用」。

**二、原文复述会让 recall@1 看起来偏低。** 有几条的事实在别处被复述过（`备注` 里都标了，
例如 zh-11 的 `11.3 billion FLOPs` 在 p.7 正文重复了一次）。标注页取的是**首次给出该事实的位置**。
命中复述页算未命中——严一点，因为读者点引用是想跳到定义处。若某个候选反复栽在这类条目上，
在报告里单列，不要混进主指标里解释。

## 语料特点（会直接影响读数）

1. **ResNet 是双栏，`pdftotext` 的读序会断。** 最明显的是 p.8：右栏文字排在左栏之前，
   一个完整的因果句被切成两段（zh-13 / en-04 就压在这里）。pdf.js 的 `getTextContent()`
   顺序问题同源，正是 `architecture.md` 点名的「分块缺口」。这条会同时压低所有候选的分数，
   但压低的幅度可能不同——它是切块缺口的探针，不是 embedding 的锅，读数时要分开归因。
2. **公式密集页的可用词面极少。** DDPM p.3 有 6 个带编号公式（(5)–(10)），p.4 有 3 个
   加上两段伪代码（Algorithm 1/2）；且文本层会**整体丢弃 `ϵ`**
   （`ϵθ` 抽出来只剩 `θ`），下标全被拍平成同行字符。zh-18 就是压这一点：
   靠词面匹配基本没戏，只有语义 embedding 有机会。
3. **表格在文本层里散成裸数字。** ResNet Table 1 的 `FLOPs` 行标题被丢掉，只剩
   `1.8×109 3.6×109 …`；Transformer Table 1 的表体按列拆成短行。表格块因此又短又没上下文，
   是最容易被相似度打分排到后面的一类（zh-07 / zh-11 专测这个）。
4. 三篇首页都有 arXiv 侧边水印（`arXiv:1512.03385v1 [cs.CV] 10 Dec 2015` 等），
   每页末尾有裸数字页码，DDPM 首页还有 NeurIPS 页脚，Transformer 首页有 Google 的版权声明。
   600 字符硬切会把它们混进正文块里，属已知本底噪声——zh-08 / zh-15 的标注页恰好都是首页，
   受这层噪声影响最大。

## 这套 eval 判得了什么、判不了什么

`research-embedding-shortlist.md` §5.3 给了一套「要判模型选型，eval 必须满足」的条件：
**query 数 ≥ 150–200、语料几十篇论文（上万块）**。理由是实证的——MIRACL-HN zh 有 393 条
query，就已经让 0.0127 的差距无法判读；Belebele 只有 488 段语料，recall@10 直接饱和到
0.969/0.989。

**本数据集是 3 篇论文、29 条问题，不满足那套条件。** 预期的候选间差距是 3 个百分点，
在 20 条中文题上就是 0.6 条题——噪声比信号大。

所以：

| 问题 | 这套 eval | 说明 |
|---|---|---|
| 换上 embedding 能不能修好「中文问英文论文零召回」？ | **判得了** | 现基线是 0，预期是几十个百分点，效应量比噪声大一个数量级 |
| 双栏读序修好后检索有没有改善？ | **判得了** | 同一模型前后对比，配对比较，且 `zh-13`/`en-04` 是专门压在 ResNet p.8 断句上的 |
| `grounding: 'none'` 会不会被新方案破坏？ | **判得了** | 3 条 `na-*`，但必须与中文 recall 并排看（见上文陷阱） |
| **embeddinggemma vs gte vs bge-m3 哪个好？** | **判不了** | 效应量 3 个百分点，样本量差一个数量级 |

**要判模型选型，得先把数据集扩到 150–200 条 query、语料扩到几十篇论文**，并保留
per-query 结果做配对检验（paired bootstrap）——那正是 MTEB 存档给不了而我们能给的东西。
在此之前，选型只能按体积、许可、工程复杂度这些**非质量维度**决定，并如实说明这是
在质量未判的前提下做的选择。

## 两类「答不了」考的不是一回事

`na-*` 三条里其实有两种，2026-08-14 起分开报：

| | 题 | 问的主题在文档里 | 检索该不该找到东西 |
|---|---|---|---|
| **主题不在** | `na-01`（语音识别词错误率）、`na-02`（语义分割 mIoU） | 否 | 不该——找到就是编造 |
| **主题在、事实不在** | `na-03`（ImageNet 上的 FID） | **是**（满页 FID 表格） | **该**——那确实是最相关的段落 |

`na-03` 检索到 FID 表格**不是失败**。按 `chat-retrieval-interface.md` 定的语义，
`grounding: 'retrieved'` 承诺的是「检索到主题相关的原文」，不是「答案确有原文支撑」
——后者要把原文读一遍才知道，是推理不是检索。

所以 **abstention 这个指标只对「主题不在」那一类有意义**。把 `na-03` 算进去会得出
「检索不诚实」的错误结论，而它其实做对了。实测两路信号（向量、关键词）在 `na-03`
上同时失效，正说明这不是靠检索能解决的。

`na-03` 仍然留着，但记的是另一件事：**它是最容易诱发模型编造答案的输入**。将来若要
测「模型拿到相关但不含答案的原文时会不会硬编」，它是现成的样本。


## 摘录进检索池（`--clips`）

`npm run eval:clips` 先拿真实模型把 `eval/samples/` 的 19 张样本认成摘录，缓存到
`clips.json`（18 条成功，p03 模型没按 JSON 回，留着不补）。缓存是为了**受控**：每次现跑
视觉识别的话，「加了摘录之后指标塌没塌」分不清是摘录的作用还是模型抖动。

### 主指标：没塌

|  | abstention | zh@3 | en@3 | 中文 margin 中位 |
|---|---|---|---|---|
| 摘录不在池 | 2/2 | 85.0% | 100.0% | 0.135 |
| 摘录在池 | 2/2 | 85.0% | 100.0% | 0.135 |

这是**这次要验的主要问题**：`MIN_PEAK_MARGIN = 0.10` 是在「只有正文块」的背景分布上标定
的，往同一个池子里掺进另一个总体（摘录短而密）有可能把中位数抬起来、让尖峰判据失准。
实测各题 margin 变动 ≤ 0.001，abstention 与 recall 一个数都没动。

### 摘录题：+1 题，且排序明显变好

| | recall@3 |
|---|---|
| 摘录不在池 | 83.3% (5/6) |
| 摘录在池 | 100.0% (6/6) |

**别只看这两个百分数。** 分母是 6，差的是一条题。基线能拿到 5/6 是因为文本层虽然给不出
公式和图的内容，却给得出图题、表题和周边正文——主题词从那里漏了出来。真正的变化在排序：

```
cl-04  p.3/13/15  →  p.3/3/3     图的内容
cl-05  什么都没有  →  p.6/6/6     表的内容（基线唯一的未命中）
cl-06  p.6/5/4    →  p.4/6/5     正确页从第 3 位升到第 1 位
```

而 `ask` 只取 top-1 喂给模型，所以「正确页在第 3 位」和「在第 1 位」对读者是两种结果。

### 这套 eval 仍然判不了的事

摘录题只有 6 条、语料 3 篇。它能回答「摘录索引有没有破坏原有指标」（效应量为零，清楚）
和「有没有带来召回」（+1 题 + 排序改善，方向清楚），**判不了**「切块该多细」「合库还是
分库」这类需要几个百分点分辨率的问题——同 `issues/01` 里对选型的那段说明。


## 生产与 eval 的参数曾经对不上（2026-08-17 修正）

这套 eval 一直跑在 `limit = 3`，而**生产只喂 top-1**。两个后果：

1. 汇报的 **zh@3 = 85% 是模型看不到的数字**——它实际只有 zh@1 = 45% 的机会拿到正确
   那段。README 开头那句「k 取实际喂给 LLM 的块数」当时并不成立。
2. 更隐蔽：`searchChunks` 的融合深度是 `limit * 3`，所以两边**连排第一的那块都不保证
   是同一块**。也就是说生产的 top-1 并不等于这里量出来的 recall@1。

现在生产也是 3（`TOP_K`），两边第一次跑在同一套参数上。曲线本身没变（eval 的口径没
动过），变的是这些数字终于描述了模型真正看到的东西。

**这套 eval 量的是检索，不是回答。** 多喂两块可能引入无关材料、把模型带偏——那个
问题它答不了，需要另一套针对答案质量的 eval。当前的缓解只有三条：每块标出页码、
prompt 说明「只能基于它」、整组材料共用同一个尖峰门槛。


## 追问（`fu-*`，2026-08-17）

量的是「读者接着上一句往下问」时检索还找不找得到。查询由生产的 `retrievalQuery` 拼，
**不是这里再实现一遍**——eval 与生产在参数上对不上的亏已经吃过一次。

|  | 追问题 recall@3 |
|---|---|
| 只取最后一轮（旧） | 77.8% (7/9) |
| 带上上一个问题 | **100% (9/9)** |

主指标一个没掉：zh@3 85%、en@3 100%、abstention 2/2、Δ@3 16.7pp、摘录题 6/6。
排序也变好——fu-02 从 `p.4/5/9` 变成 `p.5/5/4`，fu-05 从 `p.4/15/2` 变成 `p.2/2/15`。

### 一个被数据推翻的假设

前六条追问题是照「追问没有主题词」这个假设写的，**实测 6/6 全中**——因为它们其实都
还保留着主题词（「训练」「反向」「缩放」）。假设错了，题也就没测到该测的东西。

补了三条**退化追问**（「那它呢」「那要多久」「再详细点」）才找到真正的失败边界：
fu-07、fu-08 **什么都检索不到**——它们正确地 abstain 了，可读者要的答案明明就在上一问
指的那一段。改动的价值全在这三条上。
