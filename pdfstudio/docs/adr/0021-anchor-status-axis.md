# ADR-0021：第三根轴——「还找不找得回去」

## 状态

Accepted（2026-08-20）

## 背景

要给 Reader 加浏览器：在同一个应用里打开网站，同样拖框产生摘录。调研
（`docs/research-web-anchoring.md`）的第一条结论就否掉了「照搬 PDF 那套」：

> **PDF 的锚点是一个坐标；网页的锚点是一次检索。**

| | PDF | 网页 |
|---|---|---|
| 锚点是什么 | `{ page, rect }`，文件里的客观事实 | 一组关于内容的**描述**，下次要拿去**找** |
| 会不会失败 | 不会。失败 = bug | **会。失败是正常路径** |
| 失败了怎么办 | 修 bug | 要有状态、有 UI、有证据 |

**现在的 `Anchor` 扩展不到网页——不是字段不够，是它没有「可能找不到」这个概念。**

## 决策

加一根轴，与 `state`（发布：capturing → ready → promoted）和 `important`（保留）**正交**：

```ts
type AnchorStatus = "anchored" | "fuzzy" | "orphan" | "pending";
```

必填，不是可选——漏一个调用点就是 TS 报错，不是默默当 `anchored`。PDF 框选出来的
一出生就是 `anchored`。

**`fuzzy` 这一档是我们比 Hypothesis 多出来的。** 它没有分数阈值，有候选就采纳
（`match-quote.ts`），因为它是**公共标注层**：锚错了，用户看见高亮划在旁边一句上，
自己会发现，代价小。

我们是**个人知识库**：摘录会 `promote` 进知识图、切块做 embedding、被检索出来当证据。
**一条静默错锚会污染下游一整条链路，而且没人会去核对。** 宁可多几个要人确认的，
也不要一个悄悄锚错的。

## 决策 2：锚不回去的摘录不回收

`decay`（ADR-0012）会把 `content`、`sourceText`、`translation` **全部抹掉**。原来的
论证写在守卫的注释里：

> 原文、译文、截图都能按锚点重新识别一次拿回来，**笔记不能**。

**那句话有个没写出来的前提：锚点还找得到。** 它在 PDF 上永远成立——文件在磁盘上，
随时能重框一次。锚不回去的时候不成立：**存下来的这份就是仅存的副本。**

对网页摘录更狠：`sourceText` 就是 `exact`，**它本身就是锚点**。抹掉之后这条摘录
永远再也锚不回去，连「变成 orphan」这个状态都是终局。

所以 `anchorStatus !== "anchored"` 一律不回收——`fuzzy` 和 `pending` 也在内：
前者还没被确认，抹掉引文就再也确认不了；后者压根还没试过。

## 为什么现在就做，而不是等网页那条路

**这一档不做，后面全白做**——没有地方安放「找不到」这个结果。而它是纯模型改动：
一个类型、一个字段、一个动作、两条守卫，代价很小。

先把概念建出来，选择器、模糊匹配、证据快照才有地方挂。

## 代价

1. **PDF 语料里这个字段恒为 `anchored`**，看着像冗余。接受：它标记的是一个**真实存在
   但在 PDF 上恒真**的性质，而不是没用的字段。等网页那条路进来，它会立刻有值。
2. **旧摘录文件没有这个字段**，读成 `anchored`（照 `important` 的先例）。读成别的会让
   回收器突然放过一整批老摘录——那是静默的行为变化。
3. **`fuzzy` 需要一套确认 UI**，而现在还没有。在网页那条路做出来之前，它是一个到不了
   的状态。写下来是为了别忘。

## 边界

- **不在这一档定义网页的 `Region`。** 那要连着选择器一起设计（研究文档 §5.2），
  这里只建「找不到」这个概念。
- **不改 `Anchor`。** PDF 的锚点没有变。
