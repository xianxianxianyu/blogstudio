# ADR-0019：框选不再自动调模型——先出工具条，再决定去哪儿

## 状态

Accepted（2026-08-20），推翻 ADR-0016 决策 4

## 背景

ADR-0016 的决策 4 是「默认动作立刻发生」：松手即开始翻译，菜单同时浮出来。它当时的
论证是——

> 代价是「只想高亮」时也会花一次翻译调用。文本路由的原文来自文本层、是免费的，
> 唯一的成本是那次翻译——**很便宜**，换主路径不变，划算。

**那个「很便宜」现在是错的，因为语料换了。**

ADR-0016 是对着英文论文写的：有文本层（原文免费）、需要翻译（译文有价值）。而这个
应用现在主要在读的是**中文技术书**：

| | 英文论文（ADR-0016 的假设） | 中文扫描书（现在的实际） |
|---|---|---|
| 文本层 | 有，原文免费 | **没有**，每一框都是视觉调用 |
| 翻译 | 有价值 | **没有价值**——本来就是中文 |
| 一次框选的成本 | 一次便宜的翻译 | **本机 20 秒起**（实测单栏 OCR ~16s，2000px） |

所以「随手划一下」在新语料上不是零成本，而是**每划一次就占住引擎几十秒、而且产出
多半用不上**。决策者的原话：「每次都画框立马识别不太好。」

## 决策

**框选只建摘录和锚点，一个模型都不调。**

松手之后在选区旁边浮出一条工具条，读者从这里决定这个选区去哪儿：

1. **复制截图**（不调模型）
2. **导入 context**（下一步做）
3. **做笔记** —— 换成第二级面板：标记调色盘 + 一个够大的备注框
4. **问这段** —— 需要原文，图区在这一刻才认

高亮仍然是零点击的：**什么都不做得到的就是高亮**（ADR-0016 决策 3 不变）。

## 什么没有变

- **不设模式工具栏**（ADR-0016 决策 1）。这条工具条出现在**看得见选区之后**，不是
  动手之前——它不要求读者预先声明意图，那正是 ADR-0016 拒绝工具栏的理由。
- **文本路由的原文仍然免费取**。它不花钱也不花时间，没有理由推迟。
  推迟的是**翻译**与**视觉识别**这两个真正要调模型的动作。

## 代价

1. **英文论文那条路变慢了一步。** 以前松手即开始翻译，读者抬眼就有译文；现在要点一下
   再等。这是真实的退步，而且正是 ADR-0016 当初要买的东西——只是那笔买卖的价格在
   新语料上变了。真的两边都要，出口是「按文档记住偏好」，不是回到无条件自动。
2. **摘录可能长期没有内容**：只有截图和锚点。检索池里它就是一条只有位置的记录。
   ADR-0012 的墓碑已经是这个形状，所以不是新状态，但现在它会常态出现。
3. **工具条要找空位**。选区可能贴着页面边缘、也可能很大。摆不下时的退路必须明确，
   否则会出现「菜单飘在屏幕外」这种没法自证的 bug。
