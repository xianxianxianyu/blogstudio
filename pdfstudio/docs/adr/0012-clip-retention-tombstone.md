# ADR-0012：摘录的保留轴——重要标记与墓碑式衰减

## 状态

Accepted（2026-08-15）

## 背景

真实使用场景（决策者自述）：日常主路径是「划一下、看懂、过」。绝大多数摘录看完就不再
回头，真想再看多半会重划一次——重划的成本很低（拖一下 + 一次调用）。

而 ADR-0011 让一条摘录 = 一个文件夹 + 一张截图字节。一次密集阅读能产生几百条、几十 MB。
**全部永久保留，代价与价值不匹配。**

同时另一个需求出现：在原 PDF 上按 `anchor` 画标签，点开即对应摘录。它最独特的价值不是
取回内容（重划就能取回），而是**「这儿我来过」**——三个月后重开论文，标签疏密就是当初
的注意力地图。这个价值几乎全部由那些「随手一划、没保留」的摘录承载。

两个需求正面冲突：**要省存储就得删，要留痕迹就不能删。**

## 决策

1. 新增一根**保留轴**，与既有的 `state` 发布轴正交。摘录可标记为「重要」。
2. 未标记的摘录在 N 天后**衰减为墓碑**：删 `.asset/` 与正文，保留 frontmatter 里的
   `anchor`。N 默认 7，可配，**从最后一次查看起算**而非创建。
3. 重要标记存在 `index.md` 的 frontmatter。数据库索引它，但不拥有它。
4. **已入库（`promoted`）的摘录，回收器绝不能碰**，无论是否标记重要。
5. **写过笔记的摘录也不回收。**（实现时补的一条，见下）

## 为什么

**两根轴不能合并成一根。** promote 有一条硬前提：`sourceText === null` 时拒绝
（纯图没有原文，不能作为 evidence）。所以**纯图永远无法 promote**。若拿 `promoted`
当「重要」用，一张关键的架构图截图（`image` 类型）就标不了重要，第 N 天必被回收
——恰恰是最该留的东西。这不是理论风险，是把两根轴合并后的必然结果。

**删内容、留锚点。** 存储压力几乎全在截图上（几十 KB），锚点约 50 字节。删前者省掉
99%，留后者让标签存活。点击墓碑可按锚点重新识别一次——那次调用重划时本来也要付。
一句话：**痕迹是永久的，内容是会过期的。**

**flag 必须在 frontmatter。** ADR-0011 定了「文件是唯一真相，数据库是可重建的缓存」。
flag 只活在库里的话，某天索引损坏、扫文件夹重建，**全部重要标记随之丢失**，紧接着
回收器把它们静默删掉。**一次索引重建 = 一次数据毁灭。**

**笔记不能自动删。** 原文、译文、截图到期后都能按锚点重新识别一次拿回来——那正是墓碑
成立的前提。**笔记不能**：它是读者自己写的，删了就永远没了。所以规则从「内容都可过期」
收紧为「**可再生的内容才可过期**」，写过笔记的摘录整条不回收。这条是实现时才想清楚的，
原始决策里没有。

**promoted 不可回收。** 它的 Context 已经发布进共享知识库（`docs/adr/0001`），删掉
evidence 会让另一个产品那侧挂空。这是跨产品的硬约束，不是可调的本地策略。

## 代价

1. **自动删除是破坏性且不可逆的。** 默认 7 天，对一个用户可能压根没注意的行为偏激进。
   缓解在于墓碑——真正丢掉的只有可重建的内容，不是痕迹。首次运行必须显式告知该策略。
2. **「最后一次查看」要求记录访问时间**，于是读操作也要写盘。
3. **墓碑的重新识别依赖原 PDF 还在书架上。** PDF 被删则墓碑只剩标签、点不开。这与
   ADR-0011「读者可能把 PDF 删掉，摘录不该跟着失效」的理由**部分冲突**：对标记为重要
   的摘录那条理由仍然成立（截图永久保留），对未标记的我们接受这个降级。
4. frontmatter 多一个字段，schema 版本要动。

## 与「主动删除」的关系

两者看着都在删东西，规则却是**相反的**，不能合成一个操作：

| | 谁触发 | 已入库的 | 磁盘 |
|---|---|---|---|
| 主动删除 | 读者 | **允许**（context 标记 `sourceClipDeleted`——来源没了要如实标出） | 整个文件夹 |
| 回收 | 定时器 | **绝不** | 只清 `.asset/` 与正文，留锚点 |

主动删是读者的选择；回收器没有资格替读者做这个选择。合并必然牺牲其中一条。

能共用的是**机制**而不是规则：`ClipStore.save` 本来就是整体替换（写 `.tmp` → `rm`
目标 → `rename`），存一条 `content` 为 null 的摘录旧字节自然就没了。所以
**回收不需要给 `ClipStore` 加任何方法**——加一个 `decay()` 等于把「磁盘上留什么」
复制到第二个地方。

## 边界

- **不定摘录级检索索引怎么建**（见 `.scratch/pdfstudio-clip/issues/01-摘录级检索索引.md`）。
  这里只定一条耦合：**保留规则即索引规则**——内容过期，索引项随之过期，不另设一道
  「只索引重要的」闸门。一条规则管两件事。
- **不定标签的视觉**（`Clip.label` 的 `dot | panel` 是显示状态，与保留轴无关）。
