# ADR-0013：抽一层可测的应用层，视图用 React

## 状态

Accepted（2026-08-15）

## 背景

`app/main.ts` 已经 449 行裸 DOM：接线（谁依赖谁、先落盘还是先改内存、启动读不读盘）
和 DOM 操作揉在一起。

这不是审美问题。把这条竖切走完的过程中一共暴露 7 个 bug，**6 个在这一层**：

| bug | 在哪 |
|---|---|
| `translation` 依赖没接，译文永远不出现 | shell |
| `baseURL` 用了相对路径，模型调用必抛 | shell |
| `newId` 拿内存条数算，新摘录覆盖旧文件 | shell |
| 启动不读盘，同区域合并失效、id 重来 | shell |
| 删除先改内存后落盘，顺序反了 | shell |
| 指针坐标带小数，截图自报尺寸与真实字节不符 | shell |
| 误触阈值用页面点而不是画布像素 | 领域 |

同期领域层有 127 条测试，只产出最后那一个。

**原因不是运气。** 领域是纯的、可测的；shell 跑在浏览器里，没有任何测试覆盖，而且
这类错误**对单元测试免疫**——`recognizer.test.ts` 里每条翻译用例都显式传了 fake
translation 依赖，它们测的是「给了依赖会不会用」，从来不是「有没有给」。

## 决策

1. **抽一层 `Workspace`：纯 TS、不碰 DOM、在 Node 里测。** 它拥有「当前文档 + 当前
   摘录 + 落盘顺序」，对外只暴露意图（`openDoc` / `capture` / `markImportant` /
   `removeClip` / `editNote` …）。
2. **视图用 React。** 仓库已有 React 19 + Tailwind 4，ADR-0008 选的 assistant-ui
   也是 React——这里没有真正的备选，写下来只是为了不再讨论。
3. **暂不引入组件库。** 现在的界面是列表、按钮、文本域和一块 canvas，装一套设计系统
   买不到对应的东西。等 Chat 那侧接 assistant-ui 时再看它带进来什么。
4. **视图只调 `Workspace`，不直接碰 `ClipStore` / `Bookshelf` / `Recognizer`。**

## 为什么

**接线错误不是「小心点就能避免」的。** 上面那张表里的每一条,写的时候都觉得显然正确。
它们能活下来是因为没有任何测试能碰到它们。把接线搬进一层不依赖浏览器的代码，
这类 bug 才第一次变得可测——用已有的 `fake-model-client` 和临时目录的真 `ClipStore`，
就能钉住「删除先落盘」「启动读回摘录」「换书时摘录跟着换」这些。

**顺序是领域规则，不是实现细节。** ADR-0011 定了「文件是唯一真相，先落文件再更新
索引」。这条规则目前只活在 `main.ts` 的几行注释里，谁改一下顺序都不会有人拦。
它应该活在一个有测试的地方。

**先抽层再换 React，不能反过来。** 直接重写视图会把同一批未测的接线原样搬进组件，
只是从 449 行变成 12 个文件——bug 还在，还更难找。

## 代价

1. **多一层间接。** 视图不能直接使唤 store，简单操作要多穿一层。
2. **`Workspace` 有变成上帝对象的风险。** 缓解：按屏切分（阅读 / 设置 / 问答），
   而不是一个类装下全部。真的开始装不下时就是切分信号。
3. **React 带来构建复杂度**（JSX、组件生命周期、状态同步），而现在这个页面用裸 DOM
   跑得好好的。这笔账要等第二、第三块界面（设置、Chat）出现才回本。
4. **迁移期两套界面并存**，得保证旧的那套一直能跑，否则回归无从对比。

## 边界

- **不定视觉。** 配色、排版、交互细节属于实现。
- **不定 Chat UI**——ADR-0008 已经定了 assistant-ui LocalRuntime + Streamdown/KaTeX，
  这里只规定它同样通过应用层拿数据，不直接持有领域对象。
- **不打包**（ADR-0006）。dev server 那几条路由（`/__config`、`/__clips`、`/__docs`）
  已经预演了打包后的 IPC 边界，但真要固定下来得等界面稳定。
